## What actually works (24 claims, all verified end to end)

- **Per-customer isolated brand record: company info, identity, voice, audience, positioning, channels, goals, colours/logo** — Real and live. Isolation is app-level (bearer role + brand_id), not DB-level; see risks for the idea_state route and delete_brand gaps. Legacy had org-scoped BrandBrain (legacy/apps/api/app/models/brand.py:47-61) and Supabase RLS (legacy/supabase/schema.sql:88-99). `app/core/database.py:90-103, 219-282`
- **Every agent uses the Company Brain when generating (brand context injected into prompts)** — Yes — agents genuinely read the store. But the 'store' is one JSON row plus ≤12 memory lines; _brand_context omits products_services/summary/industry from the analyzed profile, and competitors/metrics/previous creatives never enter it. `app/ai/engine.py:76-108`
- **Learned brand memory: rules, human corrections, learnings persisted per brand and fed back into generation** — End-to-end real. Limits: exact-string dedupe only, no semantic recall, only the top 12 by kind/weight ever reach a prompt, recall() swallows DB errors and returns [] so a missing Supabase table makes memory silently vanish. `app/services/memory.py:35-51, 64-92, 115-126, 131-152`
- **Copy generation (caption, hashtags, script, slides, CTA) from an idea** — Live and verified. Factual grounding is only as good as projects.pointer (hardcoded MoreSpace project directory) or Airtable verified evidence; other brands can still get invented prices (see E2E doc §2). `app/ai/engine.py:261-314`
- **Image generation with brand lock and real logo** — Verified live this week on the fal path. Engine equivalent is a stub. Legacy static_post renders a Pillow text card, not AI imagery. `app/ai/brain.py:310-341`
- **Human approval of creatives (Approve / Edit / Reject with evidence & reason)** — Works end to end and gates live publish. The queue shows title/caption/asset only — no AI evidence, reason, expected outcome or risk as §15 specifies. Approval is a payload field, not an audit-logged state machine. `app/routes/studio.py:251-268`
- **Content calendar planning** — Produces a plan, but calendar items are never linked to creatives or the publish queue, and regeneration wipes the plan. Legacy planner is deterministic and tested (test_calendar_agent.py). `app/ai/engine.py:229-256`
- **Simulated publish / manual hand-off package (export bundle)** — Works, but it is not publishing: default mode produces a checklist for a human to post manually. The UI toast says 'Simulated publish queued' which reads as if something was scheduled. `app/services/connectors.py:104-128`
- **Email generation (newsletter / promo / nurture copy)** — Live path is real and gated by auth (_brand_or_404). Output is copy only; email_count clamped 1-7. Legacy version adds A/B subject variants and product injection but is archived. `app/routes/growth.py:22-34`
- **Real search-demand signals (SERP scraping) as an SEO data source** — Only genuinely working search-data path in the area. Cached 7 days on brand profile. Gated on APIFY_TOKEN; silently degrades to 'AI-inferred' when absent (app.js:527-530 labels it). `app/services/trends.py:16-22,40-67`
- **Pre-publish predictive scoring (virality / content priority) as a learning proxy** — App path is real and wired but is an LLM guess, not learned from outcomes. Legacy scoring/ package is largely placeholder constants; scoring_v2 service is the more real version. Neither compares predicted score to actual performance to calibrate. `app/ai/engine.py:531-548`
- **Analytics data visible in the Company Brain / coach context** — Works for what exists (manual rows + last LLM verdict). Not vector retrieval; no embeddings; the vision's 'Analytics' as a Company Brain domain is a 15-row JSON dump. `app/routes/_shared.py:247-270`
- **Approval decision on a generated creative (approve / request changes) recorded with who/when** — Real and tested. No 'rejected' state exists in the app (memory.py:147 handles it but the route refuses it). Any authenticated brand user can approve; current_user carries role but the route never checks it. `app/routes/studio.py:122-139`
- **A single approval queue / inbox the human works from** — Works. Queue is content-only (creatives table); ideas, calendars, campaigns, comms, budgets never enter it. Full table scan per request across all brands for admin. `app/routes/control.py:62-102`
- **Conversational interface grounded in the Company Brain (chat answers from real brand/workspace data)** — Real OpenRouter call, real DB data, wired to UI. Works as a Q&A coach only. Digest is truncated to 6000 chars and does not include brand memory (memory.context_block) despite that module existing. `app/routes/growth.py:48-56`
- **Dashboard screen — cross-brand command center (due today, needs review, KPIs, autopilot status, activity feed)** — Real and wired in the SPA. KPIs are counts only (no funnel/revenue). Legacy version adds cost meter and jobs but hits legacy-only routes. Legacy dashboard also embeds a hard-coded 'WHAT'S LIVE' checklist — marketing copy, not telemetry. `web/js/app.js:146-153`
- **Backend: Python + FastAPI** — Single uvicorn process; all AI work runs inside it. Engine repo (B) is not a service at all — scripts/run_stage.py invoked by GitHub Actions cron. `app/main.py:43-64`

- **Image/video/voice generation via a swappable provider (fal.ai) plus durable asset storage (vision §16 Fal.ai, Supabase Storage; §8 creative)** — The app is ahead of legacy here: real fal renders with grounded copy and the brand logo, stored in Supabase. Salvage only the MediaProvider Protocol signature and the Asset table columns. `app/ai/brain.py:34-40, 256-295, 310-360`

## Confirmed defects on the live path

_Runtime failure modes the skeptics named on claims marked working or partial. Each is a concrete way the feature fails today, not a design opinion._

- **[company-brain]** Per-customer isolated brand record: company info, identity, voice, audience, positioning, channels, goals, colours/logo — Re-running POST /api/brands/{bid}/analyze after a logo upload silently wipes the uploaded logo (brand_kit.logo/logo_b64/logo_url) and any cached trend_scan, because analyze() writes a fresh LLM-built profile dict and only setdefault()s brand_kit colours (pipeline.py:32-38). Also: a client login for brand A can POST /api/brands/A/ideas/{B's idea id}/state and mutate brand B's idea (pipeline.py:133-137).
- **[company-brain]** Every agent uses the Company Brain when generating (brand context injected into prompts) — projects.pointer() is appended outside any try/except and memory.context_block() is swallowed silently: if brand_memory reads fail (e.g. table missing on a fresh Postgres/Supabase), every prompt runs with zero memory and no error is surfaced anywhere. Also, on a brand whose analyze step never ran, _brand_context is just name+website+site meta — the 'brain' collapses to two fields with no warning.
- **[company-brain]** Learned brand memory: rules, human corrections, learnings persisted per brand and fed back into generation — recall() returns [] on any DB exception (memory.py:66-69) and _brand_context swallows context_block errors (engine.py:104-108), so a missing/renamed brand_memory table or a REST 4xx makes the whole memory layer vanish silently while the UI still shows 'Nothing learned yet'. Separately, because recall sorts rule > correction > learning and truncates at 12, once an operator has 12+ rules no correction or approval learning ever reaches a prompt again.
- **[company-brain]** Approved facts / grounded product-service facts (prices, sizes, contact) the AI may not deviate from — For any brand name not matching 'morespace' or a hard-coded project name/area, pointer() returns '' and no FACT_RULES reach the model at all — a new customer gets invented prices/phones exactly as documented in docs/E2E_NEOPOLIS_FINDINGS.md.
- **[company-brain]** Competitors stored in the brain and used by agents — add_competitor calls scraper.scrape_company on the competitor URL; the same httpx client that gets 403 bot-challenges on the brand's own site will yield 'site unreachable' battlecards built from the name alone (competitors.py:36-41) and store them flagged _scrape_ok=False.
- **[company-brain]** Market intelligence, trends and keywords retained and reused — APIFY_TOKEN is not in the live Railway variable list, so trend scans never run live: _generate_ideas gets no trend_signals and /trends returns AI-inferred hypotheses only. Keyword research (seo_research) is never persisted as brand knowledge on any backend.
- **[company-brain]** Previous content and creative history retained and consulted — Generating ideas twice for the same channel yields near-duplicate ideas because generate_ideas never sees the existing ideas table; nothing dedupes.
- **[company-brain]** Analytics / performance knowledge feeding learning — Insights live only on disk at WORKSPACES_ROOT/…/analytics/latest-insights.json; with several replicas or a redeploy without the /var/data volume they vanish while metrics rows persist, so ideas silently stop being insight-aware. (Live Railway config does mount a volume at /var/data and sets WORKSPACES_ROOT, so on the current single-replica deploy the file most likely survives — 'ephemeral' in the claim is overstated for live, but the design is still filesystem-bound.)
- **[company-brain]** Stored in PostgreSQL/Supabase with provisioned schema — On the Supabase REST path init_db is a no-op and there is no migration in the repo, so brand_memory/agent_runs/competitors/users do not exist unless created by hand — recall() then returns [] silently. On the live Postgres path the tables are created by CREATE TABLE IF NOT EXISTS at boot, but there is no versioning: any future column change requires manual ALTERs (the only migration helper, lines 201-206, is SQLite-only).
- **[orchestrator-agents]** Central Orchestrator decides what needs to be done next (dynamic planning from goal + state) — Airtable _choose_stage runs only from a webhook with AIRTABLE_WEBHOOK_SECRET + API config; with them unset the route returns 503 (routes/airtable.py:19-25). Engine run_stage has no error isolation: one agent exception aborts the remaining agents of the stage.
- **[orchestrator-agents]** Orchestrator routes each task to the correct specialist agent — Unknown style strings silently fall back to the 'post' team; a failed role inside run_agent_team aborts the whole team and only writes brain_status='error: ...' (routes/brain.py:37-38), no retry or re-route.
- **[orchestrator-agents]** Orchestrator controls what information each agent receives (context assembly / knowledge injection) — memory.context_block failure is swallowed (engine.py:100-107 try/except), so a broken memory table silently produces prompts with no brand memory and nothing is logged.
- **[orchestrator-agents]** Human approval gate enforced before creative execution and before publishing — Concrete: a client user hits POST /api/brands/{bid}/images or /autopilot with generate_images=true and paid image renders run with no approval on the creative; in the brain path, POST /proceed has no lock, so two clicks after approval start two parallel fal image+video+voice jobs (brain.py:65, ~15 min of fal spend each). Simulated publish with scheduled_for writes status='queued' unapproved; nothing consumes queued rows (grep), so it is inert rather than a bypass.
- **[orchestrator-agents]** Orchestrator decides what agent runs next (hand-off / workflow state machine) — Engine cron is broken in two independent ways: state loss (documented) AND two stages (strategy, schedule) have no workflow at all, so the Ideas->Content and Approved->Scheduled hand-offs can only happen from `run_stage all` on a laptop or CI smoke.
- **[orchestrator-agents]** Specialist agent roster: Research, Audience, Competitor, Trend, Strategy, Content, Creative, Social, Lead, Email, WhatsApp, Meta Ads, Google Ads, SEO, Google Reach, LLM Reach, Analytics, Learning — App 'agents' are stateless functions: any OpenRouter error surfaces as a 502 on the route (e.g. growth.py); engine roles produce fabricated data on every run in DRY_RUN (default true).
- **[orchestrator-agents]** Agent output schema — structured, validated output contract per agent — A finalize response that is valid JSON but a list (not a dict) makes bp.setdefault raise AttributeError inside the thread; brain_status becomes 'error: ...' and the creative is stuck with blueprint=None.
- **[orchestrator-agents]** Agent audit log — every agent run recorded with inputs, model, cost, result, error — finish_run swallows every exception (memory.py:203-215), so a DB outage leaves runs permanently 'running' with no signal; the app records no model/cost for any run.
- **[orchestrator-agents]** LLM provider adapter — agents contain no provider-specific logic; swappable via adapter — App: an OpenRouter 429/5xx raises httpx.HTTPStatusError once with no backoff; inside daemon threads (blueprint, autopilot) it only lands in brain_status/AUTOPILOT log text.
- **[orchestrator-agents]** Media provider adapters (image / video / voice / design) behind a swappable interface — _fal_wait polls with `(s.json() or {})`; a non-JSON status response raises inside the daemon thread and the creative is left at gen_status='Rendering image…' with no retry; a COMPLETED result lacking images returns None and the code proceeds to text-to-video with image_url=None (brain.py:105-113).
- **[orchestrator-agents]** Continuous orchestration loop — agents run on a schedule without a human click, closing Analyze → Learn → Strategy — CRON_KEY unset => cron is a bare keep-alive; a running _auto_cycle thread is killed on Railway redeploy with last_auto_cycle already stamped (autopilot.py:53-55), so that brand skips a full week silently.

### tenancy-security
_§3 isolated Company Brain; cross-cutting_

The live app (A) is a single-operator agency tool, not a multi-customer SaaS: the tenant unit is a brand (no org), there are two roles (admin/client), one admin owns every brand, and isolation is enforced only by two helper functions that are applied inconsistently — three brand-scoped routes still read/mutate other brands' ideas and creatives by raw id (/api/brands/{bid}/ideas/{iid}/state, /creatives with idea_id, /images with creative_id), the authenticated /workspaces router serves any brand's files to any logged-in user, and production requires PUBLIC_WORKSPACES=true so every generated asset is world-readable; Supabase Storage bucket URLs are public regardless. Connector tokens are stored as plaintext JSON in connector_settings; AI/provider keys are global env vars; there is no RLS, no DB migration in the repo, no rate limiting, no token revocation, no MFA, no user-action audit trail; tokens are 30-day HMAC blobs signed with a key that defaults to "dev-secret-change-me" and never checked against the DB. DIRECT_ACCESS bypass exists but is fenced by a boot-time guard with tests. The engine (B) has zero tenancy — one brand from config/brand.yaml, all secrets from process env. Legacy (C) has the real multi-tenant skeleton (orgs → users with 6-role RBAC → brands with org_id, JWT+bcrypt, Fernet-encrypted publish-target credentials, TOTP 2FA, per-org cost cap, subdomain→org middleware) but it is archived, has its own holes (2FA verify-login skips the password, SSE streams any job to any token, ApiKey table unused, no RLS), and is written against a different schema (SQLAlchemy/Alembic, sport-vertical brands). The gap to a real multi-customer SaaS: an org layer above brands, org-scoped users/invites/password reset, consistent tenant-scoped data access (ideally RLS or a repository that always filters by brand/org), encrypted per-tenant secrets, private storage with signed URLs, per-agent permission/approval rules and an audit log, and basic hardening (bcrypt, revocable sessions, rate limits).
